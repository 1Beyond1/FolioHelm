# FolioHelm：已确认的产品决定

状态：2026-08-09 已由用户确认或授权主模型代为决定。当前没有需要用户继续阅读或回答的产品问题。

完整技术方案见 `implementation-plan-v2.md`；本页只保留人需要知道的结论。

## 1. 平台

- 先做 Windows。
- macOS 和 Linux 后续再评估，不拖慢 Windows 首发。

## 2. 发布顺序

1. Mock 演示版：全是虚构数据，不连接 Schwab，让大家先体验 UI。
2. 只读连接版：能看真实账户和行情，但编译时没有下单、撤单和改单能力。公开前先确认 Schwab 当前分发条款。
3. Preview-only：能填写订单并让 Schwab 检查，但没有最终提交能力。
4. 实验性真实交易版：最后单独开放，必须通过安全、合规、来源完整性和小额人工测试；Windows 付费签名推荐但不强制。

## 3. 首个真实交易范围

- 只做股票和 ETF。
- 只做正常交易时段的手动 Limit Order。
- 支持买入和卖出现有多头持仓。
- 首版可 Place 和 Cancel；Replace 等状态语义验证充分后再开放。
- Market Order 只能 Preview，不能真实提交。
- 首版不做期权、卖空、主动保证金借款、扩展时段、自动策略或高频交易。
- 自动提醒、自动草稿、自动 Preview、定时执行和无人值守交易保留为后续分级能力，不作永久排除。
- 高频连续 Place / Cancel / Replace 只做独立可行性研究；若当前 Schwab API、限流和本地桌面架构不能把风险控制在可接受范围，就不发布该能力。

## 4. “不确定就只读”

只读是指：仍可查看真实账户、余额、持仓、行情、订单和流水，但不能调用会改变账户的 Place、Cancel 或 Replace。

如果软件无法确认账户权限、可用资金、可卖数量、市场状态、报价新鲜度、订单结果或 API 契约，就继续显示可靠数据和具体原因，同时关闭对应交易动作。条件恢复并重新验证后才开放。

## 5. 安全设置

- Settings > Trading Safety 提供单笔金额、每日金额、单笔数量、限价偏离、自动锁定和账户白名单，默认全部开启。
- 用户可调整附加保护；关闭单项时必须阅读阻塞式风险说明、滚动到底、等待 8 秒、勾选确认，并对高风险项输入确认短语。
- 关闭后立即锁定交易会话并作废已有 Preview。
- 有效 Preview、订单哈希、单次 Nonce、账户一致、精确小数、关键数据新鲜度、写请求不重试、Unknown 先对账、凭据隔离和独立确认窗口属于核心保护，不能关闭。

## 6. 语言

- 首次启动跟随 Windows 系统语言。
- 内置 English 和简体中文，用户可在 Settings 覆盖。
- 未支持的系统语言回退 English。
- GitHub README 和公开截图默认用 English。

## 7. 许可证

- Apache License 2.0。
- 仍需非官方声明、无投资建议声明、风险说明，并遵守 Schwab 当前条款和市场数据许可。

## 8. Windows 代码签名

- 现在不购买，先把软件做好。
- 付费 Windows Authenticode 不是普通 EXE 运行和 GitHub 上线的硬要求，也不能保证交易程序没有 Bug。
- 不买签名时，使用公开 CI、SHA-256、SBOM、GitHub Artifact Attestation、不可变 Release 和可复现构建说明验证来源，并明确提示这是 unsigned build。
- 首发关闭自动更新；以后启用 Tauri Updater 时使用它自己免费生成的更新签名密钥。
- 真实交易版可以在没有付费 Authenticode 的情况下发布，但其他安全、合规、来源验证、审计和小额测试门槛一个都不能少。
- 用户量增长或进入 Microsoft Store 时，再评估购买 Authenticode / Artifact Signing。

## 9. Schwab 仍需在开发阶段核验的事实

这些不是当前要用户做选择，而是 Phase 0 的真实性门槛：

- 登录后当前官方端点、Schema、OAuth、Token 生命周期、Streaming 和限流。
- Preview 是否计入订单请求限额以及返回哪些费用与拒绝原因。
- Schwab 当前条款是否允许自动策略、定时执行、无人值守和高频订单操作。
- 免费开源分发、用户自带 Developer App 应归 Individual 还是 Commercial。
- 市场数据能否本地缓存、展示和用于公开截图。

在用户的 Developer App 获批后，主模型需要查看当时登录门户里的官方文档或 Schwab 的书面回复；在此之前不对真实交易发布作承诺。

## 10. 主模型与 Luna Max

- 主模型负责架构、安全边界、Schwab 契约、OAuth、凭据、精确金额、收益公式、订单状态机、真实写接口、审查和最终验收。
- Luna Max 负责已被锁定规格后的 UI、样式、Mock、普通 DTO / Mapper / Repository、测试补齐、文档和机械修复。
- Luna Max 不自行设计或修改真实交易、安全权限、凭据、限流、CSP、订单状态机或发布流程。

## 11. 关于经济损失和纠纷

- 不对外承诺“绝对不出错”或“保证不会亏损”，因为任何联网交易软件都无法证明这一点。
- 真实交易和未来自动化默认关闭，逐级启用，并通过硬限额、失败关闭、写请求不重试、Unknown 对账、Kill Switch、加密 Journal 和独立审查限制最坏损失。
- 每笔订单保留可导出的脱敏证据时间线，出现争议时能够核对是软件、网络、Broker、行情、用户输入还是市场波动造成。
- Apache-2.0 有无担保和责任限制条款，但不能替代安全工程，也不能保证消除所有地区的法律责任；公开无人值守或高频能力前需要专业法律复核。

## 12. 双端证据

- 用户本机保存完整证据：订单意图、确认、Preview、发送、Broker 响应、Unknown 与对账过程进入加密 Journal，并使用 Hash Chain 和设备签名检测修改、删除与重排。
- 项目侧或用户自托管的公证端只保存链序号、链头 Hash、设备公钥、时间、应用版本和设备签名，并返回服务端签名回执。
- 公证端默认不接收账户、Symbol、方向、数量、价格、订单 ID、持仓、余额、Token、Secret 或原始请求响应。
- 当前阶段只实现本地证据原语、Commitment/Receipt 数据结构和未来传输边界，不部署官方远端服务，也不进行网络上传。
- 远端回执能帮助发现本地尾部被截断，但不能证明 Broker 一定正确；争议时仍需与 Schwab 官方订单记录和 Request ID 对照。

## 13. 本次真实测试的用户授权边界

- 本次对话明确的真实测试总预算上限为 US$1.00，按整个测试阶段累计计算，不是每笔订单各 US$1.00。
- 该额度不是持续授权；每一笔真实订单仍必须由用户本人在软件内逐笔确认。没有明确的标的、方向、数量、限价和最终确认，不得提交。
- 软件不得自动挑选标的或替用户做投资判断。首个真实范围继续限制为用户明确指定的股票/ETF、Regular Session、手动 Limit Order。
- 不得为了凑足 US$1.00 去找仙股、OTC、杠杆/反向 ETF、期权、卖空或其他高风险标的。
- 如果当前只支持整股，或 API/账户不支持在 US$1.00 内安全完成测试，则不进行真实下单，也不通过降低标的质量来绕过预算限制。
- 任何超时、响应不明确或状态未知的订单都要冻结剩余预算，先对账，禁止重试。
